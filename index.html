MPaaS — Media Processing as a Service

A distributed media processing platform built to production patterns. Users upload images via a React UI, a FastAPI backend streams them to MinIO object storage, and Celery workers consume from a two-priority RabbitMQ queue topology to apply transforms. Progress streams back live over WebSockets via Redis pub/sub. Full observability stack: custom Prometheus metrics, Grafana dashboards provisioned at boot, and Flower for Celery monitoring — all wired up in Docker Compose.

📅 April 2025 · Backend Development

Building High-Throughput FastAPI Services: Async Patterns That Actually Scale

Most FastAPI tutorials show you CRUD endpoints. They don't show you what happens when you need to handle 500 concurrent requests hitting a service that fans out to a database, a cache, and an external API. The answer isn't more workers — it's understanding how Python's async event loop actually behaves under load. I walk through three architectural patterns I've used in production: background task offloading with Celery, connection pool sizing for asyncpg, and structuring dependency injection so your test suite doesn't require a live database. The goal is services that are fast, testable, and honest about their failure modes.

📅 November 2025 · IAM & Security

OAuth 2.0 in Practice: What the Spec Doesn't Tell You About Multi-Tenant RBAC

The OAuth 2.0 spec is thorough. Auth0's docs are good. Neither one tells you what to do when you have a B2B SaaS with ten enterprise customers, each with their own roles, their own admin users, and the expectation that Org A can never see Org B's data — even if they share the same Auth0 tenant. This post covers the token design decisions that matter: how I embed tenant context into JWTs without bloating them, how fine-grained RBAC works when roles live in your database rather than the IdP, and how refresh token rotation interacts with session management in SPAs. Plus the one mistake I see in almost every implementation: treating sub as a stable user identifier.

📅 January 2026 · AI Engineering

From LLM Call to Production Feature: What Changes When AI Enters Your Backend

Calling an LLM API is three lines of code. Shipping it as a reliable backend feature is a different problem. I've gone through this cycle enough times to see the patterns: latency spikes when the model is under load, token budgets that blow up on edge-case inputs, streaming responses that your frontend wasn't designed for, and the fun of writing integration tests when your primary dependency is non-deterministic. This post documents the production concerns I now plan for upfront — request timeout strategy, output schema validation with Pydantic, graceful degradation when the model is unavailable, and how to structure your prompts so they're versionable and testable like any other code.
